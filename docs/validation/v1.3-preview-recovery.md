# 검증 서버 연결 복구 및 화면 검수

기존 검증용 버전 6의 애플리케이션 코드는 변경하지 않았으며 운영 배포/운영 D1 변경은 하지 않았습니다.

## 연결 실패 원인

복원한 체크아웃에 `.sites-runtime/execution-profile.json`이 없어 실행기가 portable 모드로 동작했습니다. 서버 실행 정보에는 hostname 127.0.0.1, appUrl http://127.0.0.1:4173가 기록되어 있었으며 검수 브라우저의 terminal.local 접속이 거부됐습니다. 이전 dev lock도 남아 재시작 시 Another vinext dev server is already running 오류가 발생했습니다.

공식 configure-execution-profile.mjs로 managed-linux 설정을 복원하고 지원되는 sites-preview stop/start 흐름으로 재시작했습니다. 이후 같은 http://terminal.local:4173/에서 실제 게임과 게시판이 열렸습니다. 설정 복원은 Git에서 제외되는 개발 환경 상태만 변경했습니다.

## 실제 브라우저에서 확인한 항목

- 게시판 탭과 비어 있는 목록 표시.
- 방명록용 선수 이름 등록과 입력창 표시.
- 200자 입력 카운터, 글 등록, 새 글 목록 표시.
- 좋아요 0→1, 다시 눌러 1→0.
- 설정에서 선수 이름 변경 후 기존 게시글 작성자 이름 반영.
- 마을 탭 이동 후 게시판 재진입과 글 재조회.
- 삭제 확인창 표시 및 취소 후 글 유지. 실제 삭제 실행은 이 화면 검사에 포함하지 않았으며 기존 API/SQL 테스트에서 검증했습니다.
- 데스크톱 검수 브라우저의 480px 제한 레이아웃을 확인했습니다. 실제 스마트폰 키보드/터치/화면 회전 검수와 동일하지 않습니다.

이 문서는 이전 보고서의 검증 서버 연결 실패 상태가 복구되었음을 기록합니다. 애플리케이션은 기존 사이트의 검증용 버전 6에 저장된 상태로 유지되며 운영 배포 여부는 별도로 결정합니다.
