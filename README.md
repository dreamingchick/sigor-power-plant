# 시고르 발전소 — v1.3 마을 게시판 기능 브랜치

모바일 세로 전용 연타 경기와 개인 시골 마을 성장을 결합한 설치형 웹앱입니다. 밀짚모자를 쓰고 채찍과 장부를 든 까마귀 악덕 이장이 플레이어를 재촉합니다. 별도 플레이어 캐릭터는 없습니다.

## 확정 규칙

- 큰 가동 버튼 하나, 손가락 수 자유. 접촉이 없는 상태에서 새로 닿으면 1회. 모든 손가락이 떨어져야 재무장됩니다. 길게 누르기·문지르기·겹친 접촉은 추가 집계하지 않습니다. 마우스 입력은 집계하지 않습니다.
- 시작 버튼 후 3초 카운트다운. 시작 전 입력 무시, 시작 순간 누르고 있으면 모두 떼고 다시 눌러야 합니다.
- 순간 발전: 10초, 총 터치 수 순위. 70회 = 1,000점.
- 지속 발전: 60초, 총 터치 수 순위. 360회 = 1,000점.
- 블랙아웃 방어: 5초 구간별 판정. 첫 목표 20회, 3구간(15초)마다 목표 +4회. 게이지 초기·최대100, 부족1회당 -6, 초과1회당 +1. 0이면 종료. 생존 시간 → 총 터치 수로 비교, 모두 같으면 공동 순위. 생존90초 = 1,000점.
- 종합 점수: 종목별 역대 최고 기록의 환산점수 합계, 반올림 정수 표시. 미참여0점, 한 종목부터 참여, 상한 없음. 생존 동점 터치 수는 종합 점수에 영향 없음.
- 닉네임 최초1회 입력, 내부 선수ID와 기기 비밀값 발급. 계정 로그인 없음. 정상 종료 기록 자동 제출. 동일 경기ID 재전송 중복 방지.
- 일시정지 없음. 앱 전환·화면 잠금·가로 회전 시 중단, 해당 경기의 기록·에너지 미지급. 화면 잠금 방지는 지원 기기에서 요청합니다.
- 정상 종료한 유효 터치1회 = 성장 에너지1. 랭킹과 별도이며 자동 누적, 소모하지 않음. 개인 마을과 기록은 현재 기기에 저장합니다.
- 종료 후 약2초 마무리, 접촉이 모두 해제된 후 결과 버튼 표시. 평균/최고1초구간 속도, 그래프, 최고기록, 종목순위, 종합점수, 마을 평가 표시.
- 노을→밤 배경. 음악·효과음·주요순간 진동 개별 설정. 까마귀와 기계음은 합성음으로 구현했습니다.
- 오프라인 경기/성장/재실행 지원. 최초 온라인으로 Service Worker 자료저장 필요. 정상 종료 기록은 재연결·다음 실행·30초 간격으로 재시도. 앱이 완전히 종료된 동안의 백그라운드 제출은 보장하지 않습니다.

## 마을 성장표 (초기 검증 수치)

|단계|누적 에너지|시설|
|---|---:|---|
|1|0|작은 발전소|
|2|100|첫 가로등|
|3|300|농가의 불빛|
|4|700|논밭 길|
|5|1,200|물레방아|
|6|2,000|농가와 헛간|
|7|3,200|풍차|
|8|5,000|시골 장터|
|9|7,200|작은 기차역|
|10|10,000|마을회관과 광장|

완성 후 기념장식: 15,000 깃발 / 25,000 풍향계 / 40,000 기념비 / 60,000 이장 동상. 마을은 유지하며 장식은 외형만 변경합니다. 이후 장식은 후속 확장 대상입니다.

결과 등급 초안: 해당 종목1,000점 기준의 130% 이상 S / 100% 이상 A / 70% 이상 B / 그 미만 C.

- `node tests/api.test.mjs`: 실제 API 코드를 분리된 DB 어댑터에서 검사. 입력/선수인증/중복제출/생존재계산.

## 실기기 검수

1. Android Chrome으로 열기 → 닉네임 입력 → 3초 카운트다운 확인.
2. 한 손가락을 댄 채 다른 손가락 연타: 추가 집계가 없는지 확인. 모두 뗀 뒤 누르면1회.
3. 10초/60초 완주, 5초구간/15초단계 생존경기 확인. 종료 직후 연타로 결과 버튼이 오작동하지 않는지 확인.
4. 앱 전환·화면 잠금·가로 회전으로 중단 시 에너지/기록 미반영 확인.
5. 설정 → 설치 또는 Chrome 메뉴 → 앱 설치. 오프라인 준비 완료 후 비행기 모드에서 다시 열기.
6. 오프라인 경기 완주 → 등록대기 → 연결 복구 후 자동등록. 재접속해도 에너지 중복지급이 없는지 확인.
7. 별도 기기에서 고유 닉네임으로 경기, 서로의 공유랭킹 표시 확인. 다인 검증에는 사이트 접근공개 설정 필요.

## 검증판의 한계

브라우저 데이터 삭제·다른 브라우저·기기 변경 시 선수 비밀값과 개인 마을 복구 기능이 없습니다. 오프라인 기록은 클라이언트에서 발생하므로 강한 부정행위 방지는 보장하지 않습니다. 서버는 시간·터치로그·생존게이지를 다시 확인하지만 정교하게 조작된 로그와 실제 터치를 완벽히 구분할 수 없습니다. 보상·상금이 있는 대회용 검증은 별도 서버 세션 설계가 필요합니다. 실제 휴대폰 멀티터치, 진동, 설치, 비행기모드 검수는 사용자의 실기기에서 확인해야 합니다.

## v1.1 블랙아웃 방어 조정

첫 목표20회와15초 단계는 유지하고, 목표 증가를+4회, 부족분-6/초과분+1로 변경했습니다. 초당4회 고정 페이스는 기존40초에서35초 생존으로 단축됩니다. 서버도 동일 규칙으로 검증합니다. 기존 규칙의 서버 기록은 삭제하지 않고 새 규칙과 구분하며 현재 방어 랭킹과 종합점수는 새 규칙 기록만 반영합니다. 기기의 기존 방어 최고 기록도 별도 보관해 마을 화면에 표시합니다. 다른 종목과 누적 에너지는 유지합니다.

## 공유 랭킹 초기화

랭킹 구분값 `20261106-01`부터 새로 집계합니다. 이전 서버 기록은 현재 랭킹 집계에서 제외되고, 초기화 이전 앱에서 대기하던 기록도 다시 올라오지 않습니다. 새 버전 최초 실행 시 기기 내 랭킹 최고 기록과 제출대기 목록을 비우되 이전 최고 기록은 별도 보관합니다. 닉네임·선수ID·비밀값·마을 에너지·성장·설정은 유지합니다.

## v1.2 선수 정보 관리

설정 → 선수 정보 관리에서 이름 변경과 범위별 초기화를 제공합니다.

|기능|초기화/변경 대상|유지 대상|
|---|---|---|
|이름 변경 / 다시 설정|닉네임 1~12자, 공유 랭킹의 기존 이름도 변경|선수ID·기록·마을·설정|
|마을 성장 초기화|누적 에너지0, 1단계 마을, 장식 잠금|이름·선수ID·경기 기록·설정|
|개인 경기 기록 초기화|개인 최고기록·종합점수·제출대기·현재 공유랭킹의 본인 기록|마을 성장·선수 이름·설정|
|선수 정보 전체 초기화|이름·선수ID·마을·개인기록·현재 공유랭킹 본인 기록·설정|다른 선수의 데이터|

이름 변경은 오프라인에서 기기에 저장하고 재연결 시 공유 랭킹에 반영합니다. 기록/전체 초기화는 온라인에서 서버 처리가 성공해야 적용합니다. 각 초기화는 삭제 범위를 표시하는 별도의 확인 화면을 거칩니다. 서버 PATCH/DELETE는 기존 선수의 기기 비밀값을 확인하고, 개인 경기 기록 초기화는 현재 랭킹 구분값과 본인 선수ID에만 적용합니다. 전체 초기화는 본인의 이전 경기 기록까지 포함하며, 다른 선수의 데이터는 유지합니다. 운영자 전체랭킹 초기화는 이용자 설정에 노출하지 않습니다.

## v1.3 마을 게시판 (B안, 기능 브랜치)

발전소 하단 네 번째 탭 **게시판**에서 모든 기기의 방명록을 읽습니다. 기존 선수 이름/ID/기기 비밀값을 재사용하여 로그인 없이 글 작성·삭제·좋아요를 제공합니다.

- 작성: 1~200자, 본인당 30초 간격, 최근 24시간 최대 20건. 링크 및 기초 금칙어 필터. 20건씩 페이지 이동.
- 좋아요: 각 선수 ID당 게시글별 하나. 다시 누르면 취소. 기기 비밀값을 검증하며 서버에서 중복 저장을 거부합니다.
- 삭제: 본인이 작성한 글만 가능. 삭제 시 해당 글의 좋아요도 함께 삭제됩니다.
- 이름 변경: 랭킹과 과거 방명록의 표시 이름도 동기화합니다.
- 선수 정보 전체 초기화: 본인이 쓴 글과 좋아요도 서버에서 삭제합니다. 경기 기록만 초기화하거나 마을 성장만 초기화하면 방명록은 유지합니다.
- 오프라인: 이미 다운로드된 게임 화면은 열리지만 방명록 조회/작성·좋아요·삭제는 온라인에서만 동작합니다. 오프라인 작성 큐는 지원하지 않습니다.
- 글은 HTML이 아닌 일반 텍스트로 저장하며, 브라우저에서 이스케이프 처리하여 출력합니다.

### Cloudflare D1 도입 순서

기존 D1 바인딩은 **DB**이며, 공유 랭킹은 **runs** 테이블을 사용합니다. 새 테이블 **guestbook_players**, **guestbook_posts**, **guestbook_likes**, **guestbook_rate**를 db/schema.ts와 drizzle/0001_village_guestbook.sql에 정의했습니다. **운영 DB에 0001 추가 마이그레이션을 먼저 적용한 뒤 앱을 배포해야 합니다.** 기존 runs 및 마을 로컬 저장 데이터는 삭제하지 않습니다. 실제 연결된 D1 DB ID를 확인하고 마이그레이션 도구나 관리형 배포 환경의 D1 절차를 사용하십시오. vite.config.ts의 placeholder DB ID는 로컬 개발용이며 운영 DB ID가 아닙니다.

마이그레이션 적용 후 다음 SQL로 네 테이블의 존재를 확인합니다.

    SELECT name FROM sqlite_master WHERE type='table' AND name LIKE 'guestbook_%';

적용 전에는 /api/guestbook이 연결 오류(503)를 반환할 수 있으며, 이 브랜치의 변경은 실제 Cloudflare에 배포된 것이 아닙니다.

### 검증

- node tests/guestbook.test.mjs: 메모리 SQLite에 마이그레이션 SQL을 실행하고 인증, 입력 검증, XSS 텍스트 보존, 작성 제한, 좋아요, 본인 삭제, 전체 초기화 및 페이지 이동 검증.
- node tests/api.test.mjs, node tests/rules.test.mjs, node tests/account.test.mjs: 기존 랭킹과 게임 로직 회귀검증.
- pnpm exec tsc --noEmit 및 node --check public/guestbook.mjs.
- 모바일 실기기: 4개 탭 표시, 키보드 입력 후 스크롤, 2개 기기의 30초 주기 갱신, 좋아요 제한, 삭제 확인, 닉네임 변경 반영, 전체 초기화 후 글/좋아요 제거, 오프라인 메시지 확인.

보안 한계: 별도 로그인이나 CAPTCHA가 없는 익명 기반입니다. 임의의 신규 선수 ID를 대량 생성하는 스팸은 선수별 제한만으로 완벽하게 막을 수 없습니다. 공개 운영 시 Cloudflare WAF·Rate Limiting·Turnstile 또는 운영자 신고/차단 기능 추가가 권장됩니다. 선수 비밀값은 guestbook 인증 테이블에 SHA-256 해시로 보관되지만 기존 랭킹 테이블의 비밀값 저장 구조는 변경하지 않습니다.

### v1.3 보완: 트랜잭션 단위 선수 관리

- 전체 초기화는 `/api/ranking`의 DELETE 요청 한 번으로 처리합니다. `scope: account`는 본인 랭킹(이전 기록 포함)·방명록·좋아요·작성 제한·방명록 인증을 D1 batch 한 트랜잭션으로 제거합니다.
- `scope: records` 또는 scope 생략은 기존과 동일하게 현재 랭킹 기록만 초기화합니다.
- 선수 이름 변경도 랭킹과 방명록 이름을 D1 batch로 갱신하여 한쪽만 변경되는 문제를 방지합니다.
- `node tests/atomic-account-reset.test.mjs`: 5개 삭제 단계 각각에 장애를 주입해 전체 롤백 확인. 인증·타 선수 보존·이전 기록 범위·재시도·이름 변경 롤백도 확인합니다.
- 추가 스키마 변경은 없으며 신규 D1 마이그레이션은 기존 검증 버전의 0001 하나뿐입니다.
